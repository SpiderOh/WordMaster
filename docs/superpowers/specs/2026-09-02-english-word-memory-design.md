# 英语记单词程序设计规格

## 1. 目标与范围

构建一个移动端优先的英语记单词 PWA。用户可以导入多个 CSV 词库，按可配置数量（默认 15）生成竖向学习页，在纸笔背诵后以“完成本页”记录整页学习。系统保存每个词的状态、累计学习次数、每次学习日期、遗忘次数和历史快照，并提供日期浏览、遗忘词排序与导出、轻量统计、离线使用和服务器同步。

首版采用轻量模块化单体：React + TypeScript + Vite 前端，FastAPI 后端，SQLite 数据库，REST + OpenAPI，Docker Compose 部署。暂不引入微服务、Redis、消息队列或复杂第三方登录。

## 2. 已确认的产品规则

### 2.1 词库

- 每个 CSV 对应一个独立词库；词库内学习记录独立。
- 当前 CSV 字段为 `number,word,meaning,source_page`；导入至少要求 `word,meaning`，其余列可选。
- 自动去除首尾空格，英文规范化时忽略大小写；释义中的换行必须保留。
- 支持上传、重命名、优先级、激活/停用、删除和统计查看。
- 同时激活多个词库时，按用户优先级取词；同一词库内按 CSV 原始顺序取词。
- 跨词库生成新词时，若同一规范化英文词在其他词库中累计学习次数大于等于 3 且历史遗忘次数为 0，则跳过该词。只要历史上遗忘次数大于 0，就不满足跳过条件。
- 词库删除必须二次确认；删除操作进入审计日志。

### 2.2 页面与学习

- 只有一个“学习”板块，不生成会积压的强制复习队列。
- 默认每页 15 个词；用户可以修改数量。新数量只影响以后新页面；历史已完成页面保留原分组。当前未完成页面默认保持原页，可选择重排。
- 学习页竖向排列，尽量一屏看到全部词。默认只显示英文；点击单词行或眼睛按钮后，在单词左侧显示该词释义。
- 词库、原始页码、累计学习次数、遗忘次数放在小字号辅助信息区。
- 打开学习板块默认显示下一页未完成的新词，同时支持按日期查看历史页面和左右滑动切换相邻页面。
- 页面数量不足时允许少于设定数量，并显示词库接近学完的提示。
- 第一次学习时每个词可标记“熟”或“遗忘”；第二、第三次学习不显示“熟”按钮，只允许“遗忘”操作。
- “熟”只允许在第一次学习时操作。标记后立即从当前页移除并补入新词；新补入词的学习次数为 0。已完成历史页保存快照，不受替换影响。
- 点击“完成本页”后，当前页未标记为熟的词累计学习次数加 1；记录完成时间、页面快照和不可覆盖的学习事件。默认弹窗确认，支持短时间撤销。
- 未点击“完成本页”离开页面时，已执行的遗忘操作立即保存；页面学习次数不增加。
- 同一页再次学习时，只有点击“完成本页”才增加次数；访问本身不计学习。
- 推荐间隔默认是 `0、1、4` 天，可配置为任意天数列表。推荐日期只用于日历和页面提示，不强制、不形成逾期积压。

### 2.3 状态、遗忘与专攻

- 主状态只有：`未学习`、`学习中`、`熟`。
- 未学习：学习次数为 0；完成一次学习后变为学习中。
- 熟：第一次学习时手动标记；从普通新词页移除，可在已掌握词页面恢复为未学习并重新安排。
- 遗忘操作使遗忘次数加 1，并保留在原历史页面；不自动改变推荐日期，不在学习页显示“需专攻”标签。
- 单独提供“遗忘单词”入口，默认按遗忘次数从高到低排序，支持按词库、状态、最近遗忘日期筛选、单词搜索和导出。
- 遗忘入口支持跳转历史页面、批量选择单词生成专攻页。专攻完成时逐词选择“记得 / 遗忘 / 熟”：记得清除专攻集合并恢复普通学习；遗忘继续累加并保留专攻；熟改为熟状态并移出普通学习。
- 支持撤销最近一次遗忘；不允许直接输入任意遗忘次数。

### 2.4 日期与统计

- 日历显示有学习记录的日期；没有完成学习的日期自动显示为灰色。
- 推荐复习日期以浅色标记，实际完成日期以明显颜色标记。
- 选择日期后，直观看到该日期学习过哪些页面、每页处于第几次学习、第二次和第三次是否完成，以及尚未完成的推荐次数。支持日期列表、日历选择和左右滑动。
- 首页显示继续学习、下一页新词、推荐页面、最近学习日期和简单统计，不显示积压复习数量。
- 统计页显示：今日学习单词数量（遗忘也计入）、今日遗忘数量、今日再次遗忘数量及可点击明细、学习日历连续天数、累计学习次数、学习中数量、熟词数量和遗忘词数量。

## 3. 技术架构

### 3.1 模块

- `frontend`：React、TypeScript、Vite、PWA、IndexedDB 离线缓存。
- `backend`：FastAPI，按认证、词库、学习页、历史、遗忘、统计、同步、备份拆分路由和服务。
- `database`：SQLite 起步，使用迁移脚本；数据访问通过 repository/service 层，预留 PostgreSQL 迁移。
- `deployment`：Docker Compose，一个后端服务、一个前端静态资源服务和一个 SQLite 数据卷。

### 3.2 数据表

- `users`：账户、密码哈希、创建和登录时间。
- `vocabularies`：词库名称、文件名、导入时间、总词数、激活状态、优先级。
- `words`：词库、原始编号、英文、规范化英文、释义、原始页码。
- `word_progress`：用户与词的状态、累计学习次数、遗忘次数、首次/最近学习时间、熟词和恢复时间、历史遗忘标志、推荐日期。
- `study_pages`：用户页面编号、页大小、状态、创建时间。
- `study_page_words`：页面单词、显示顺序、加入原因。
- `study_sessions`：每次完成本页的时间、页面编号、增加次数、完整快照。
- `word_study_events`：学习、遗忘、撤销遗忘、标记熟、恢复熟等不可覆盖事件。
- `operation_logs`：导入、删除、激活/停用、完成页面、标记、恢复、设置和同步的前后值、时间、设备。
- `sync_records`：设备、事件 ID、同步状态、冲突结果和时间。

### 3.3 同步

- 本地操作先写 IndexedDB 事件队列并立即更新界面。
- 联网后调用 `/api/v1/sync/push` 和 `/api/v1/sync/pull` 做增量同步。
- 事件带唯一 ID、设备 ID、客户端时间、服务器时间、对象、操作和变更数据。
- 计数型字段按增量累加；事件按 ID 幂等去重；状态、页面设置和优先级按最后修改时间处理；冲突写入同步记录。
- 同步失败保留队列，显示离线/待同步状态。

## 4. API 约定

所有接口前缀为 `/api/v1`，使用 Pydantic 模型、统一错误格式、分页/筛选/排序约定，并生成 `openapi.json`。

- `auth`：登录、退出、当前用户、Token 刷新、修改密码。
- `vocabularies`：列表、CSV 上传、详情、重命名、激活/停用、优先级、删除。
- `words`：查询、详情、状态和遗忘记录。
- `study-pages`：生成下一页、当前页、按日期查询、相邻页、完成、撤销完成。
- `study-events`：标记遗忘、撤销遗忘、第一次学习标记熟、恢复熟词。
- `forgotten-words`：排序、筛选、搜索、批量生成专攻页、导出。
- `history`：按日期、词库和页面查询快照与事件。
- `stats`：今日统计、再次遗忘明细、连续学习天数、总计。
- `settings`：页大小、推荐间隔、主题、字号、词库范围。
- `sync`：推送、拉取、状态、冲突记录。
- `backup`：全量 JSON 导出/导入、词库 CSV 导出、遗忘列表 CSV 导出。

本地阶段允许无认证访问；服务器阶段启用用户名/密码和 Token。API 不直接暴露数据库实现，所有业务规则通过服务层执行。

## 5. 项目留痕与文档

项目必须包含 `README.md`、`ARCHITECTURE.md`、`DATABASE.md`、`API.md`、`SYNC.md`、`DECISIONS.md`、`CHANGELOG.md`、`AI_CONTEXT.md`、`openapi.json`、`.env.example`、数据库迁移和测试说明。每次 AI 修改前读取上下文与决策文档；修改后更新变更记录；行为改变时同步更新决策文档。禁止直接修改生产数据库，必须使用迁移脚本。
