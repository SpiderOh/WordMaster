# 英语记单词 PWA：开发总提示词

你是一名负责端到端交付的资深全栈工程师。请在当前工作区开发一个移动端优先的英语记单词 PWA。先阅读以下文件，再开始编码：

- `docs/superpowers/specs/2026-09-02-english-word-memory-design.md`
- `docs/superpowers/plans/2026-09-02-english-word-memory.md`
- `docs/AI_CONTEXT.md`
- `docs/DECISIONS.md`

## 目标

用户可以上传多个独立 CSV 词库，默认每页显示 15 个英文单词，纸笔背诵后点击“完成本页”记录整页学习。系统要保存单词状态、累计学习次数、每次学习日期、遗忘次数、历史页面快照和操作日志；支持按日期查看第 1/2/3 次学习完成情况，按遗忘次数查看和导出遗忘词，支持 PWA 离线记录、服务器同步、JSON 迁移和 OpenAPI 二次调用。

## 固定业务规则

1. 每个 CSV 是独立词库；至少要求 `word,meaning`，可选 `number,source_page`；保留中文释义换行。
2. 英文规范化忽略大小写并去除首尾空格。跨词库取新词时，若该词在其他词库累计学习次数 >=3 且历史遗忘次数为 0，则跳过；历史上遗忘过的词不跳过。
3. 只有一个学习板块，不生成强制复习积压队列。默认页大小 15，可改；新页使用新大小，历史快照不变。
4. 新词按激活词库优先级、词库内 CSV 原始顺序生成。页面不足时允许少于设置数量并提示。
5. 第一次学习时每个词可标记“熟”或“遗忘”；第二、第三次学习隐藏“熟”按钮，只允许遗忘。熟词立即从当前页移除并补入学习次数为 0 的新词。
6. 点击“完成本页”才给当前页未熟词学习次数 +1，并记录时间、快照和不可覆盖事件；默认二次确认并支持短时撤销。离开未完成页面时，已执行的遗忘操作立即保存。
7. 主状态为 `未学习 / 学习中 / 熟`。熟词可在已掌握页面恢复为未学习。遗忘只累计次数，不显示需专攻标签，不自动修改推荐日期。
8. 推荐间隔默认 `0,1,4` 天，只用于日历和提示，不强制、不累积。无学习日期显示灰色；实际学习日期和推荐日期使用不同颜色。
9. 遗忘入口默认按次数降序，支持词库/状态/日期筛选、搜索、CSV 导出、历史页跳转和批量生成专攻页。专攻逐词选择记得/遗忘/熟。
10. 统计显示今日学习词数（遗忘也算）、今日遗忘数、今日再次遗忘数及明细、连续学习天数，以及累计学习、学习中、熟词、遗忘词数量。

## 技术约束

- 前端：React + TypeScript + Vite + PWA + IndexedDB。
- 后端：FastAPI + Pydantic + SQLAlchemy/SQLModel + Alembic。
- 数据库：SQLite 起步，repository/service 分层，预留 PostgreSQL 迁移。
- API：REST，前缀 `/api/v1`，生成 `openapi.json`。
- 部署：Docker Compose，适合小型服务器；不要引入微服务、Redis、消息队列或重型框架。
- 本地开发默认免登录；服务器模式使用用户名/密码和 Bearer Token。

## 实施要求

1. 严格按实施计划逐任务开发；每个任务先写失败测试，再写最小实现，再运行测试。
2. 先完成后端数据模型、导入、学习页和 API，再完成前端页面，最后完成 PWA、同步、认证和部署。
3. 所有业务规则放在服务层，路由只做参数校验和响应转换；前端不得自行推导权威统计。
4. 所有重要操作追加 `word_study_events` 和 `operation_logs`，不能通过覆盖记录丢失历史。
5. 同步事件必须有唯一 ID、设备 ID、客户端时间和幂等处理；计数按增量累加，状态与设置按最后修改时间合并，冲突写入 `sync_records`。
6. 每次修改前读取 `AI_CONTEXT.md` 和 `DECISIONS.md`；修改后更新 `CHANGELOG.md`，行为变化同步更新决策记录和 AI 上下文。
7. CSV 导入错误行单独报告，不阻塞有效行；备份导入必须有版本号、校验和事务回滚。
8. 测试至少覆盖 CSV 导入、重复词规范化、跨词库跳过、页大小、熟词替换、页面快照、学习次数、遗忘/撤销、再次遗忘统计、日期历史、同步幂等、备份恢复和认证。
9. 完成后运行后端测试、前端测试、类型检查、生产构建和 Docker smoke test，并在 `AI_CONTEXT.md` 写明结果。

## GitHub 工作流

- 工作目录是仓库根目录；开始前运行 `git status` 和 `git log -5 --oneline`。
- 每个可独立验证的任务完成后创建一次小提交，提交信息使用 `feat: ...`、`fix: ...`、`docs: ...` 或 `test: ...`。
- 提交前检查 `git diff --check`，确认没有密钥、`.env`、数据库文件或个人隐私。
- 如果当前环境已配置 GitHub 凭据且用户允许推送，可执行 `git push origin main`；否则只提交本地并报告待推送命令。
- 不要修改仓库公开/私有设置，不要强制推送，不要重写已有提交历史。
- 每次报告必须包含：完成内容、修改文件、测试命令及结果、提交编号、是否已推送、下一步任务。
