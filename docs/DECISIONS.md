# 设计决策记录

## 2026-09-02：采用模块化单体

选择 FastAPI + React/TypeScript + SQLite + Docker Compose。原因是适合小型服务器，同时保留清晰 API 边界和 AI 二次开发能力；不引入微服务、Redis 或消息队列。

## 2026-09-02：单一学习板块

不生成会积压的强制复习队列。学习日期和推荐日期用于主动浏览与提示，逾期不累积、不强制。

## 2026-09-02：历史快照不可变

每次完成页面保存完整单词顺序和状态快照，后续熟词替换或页大小改变不得修改历史。

## 2026-09-02：熟词只允许首次学习标记

首次学习可标记熟，第二、第三次隐藏熟操作。熟词立即从当前未完成页移除并补入学习次数为 0 的新词。

## 2026-09-02：跨词库跳过

词库学习记录独立；生成新词时，若其他词库同规范化单词学习次数 >=3 且历史遗忘次数为 0，则跳过。历史上遗忘过的词永不满足跳过条件。

## 2026-09-02：同步合并

事件按唯一 ID 幂等去重；次数按增量累加；状态、设置和优先级按最后修改时间；冲突写入同步记录。

## 2026-09-04：完成撤销窗口

页面完成仅允许撤销最新的未撤销会话，默认窗口为完成后 300 秒。撤销后从剩余有效会话恢复页面完成状态及单词首末学习时间；若不存在剩余会话，页面才恢复为未完成。

## 2026-09-04：专攻集合独立状态

历史遗忘次数只通过追加事件累计或抵消，不用于表达当前是否仍需专攻。`word_progress.needs_special_attention` 单独记录专攻集合状态：普通遗忘与专攻中再次遗忘设为真，专攻中记得或标熟设为假。

## 2026-09-04：今日再次遗忘定义

某词今天发生有效遗忘，且此前已经存在至少一次未撤销的遗忘，即计为一个“今日再次遗忘单词”。同一单词今天多次遗忘仍按一个单词计入明细，今日遗忘总数则按有效事件数统计。

## 2026-09-04：JSON 备份事务替换

JSON 备份使用显式版本号并包含当前用户的词库、单词、进度、页面、会话、事件和设置。导入先校验所有引用，再在单一事务中替换当前用户数据；校验或写入失败时保留导入前状态。

## 2026-09-04：本地免登录与服务器 Bearer Token

本地模式固定使用本地用户以降低单机启动成本；服务器模式要求用户名/密码登录，密码使用 PBKDF2-HMAC-SHA256 哈希，访问令牌使用 HMAC 签名并保存可撤销的 jti。健康检查和登录保持公开，业务接口统一验证令牌；令牌本身不写入数据库。

## 2026-09-04：同步批次原子化与单调游标

一次同步推送作为单一事务处理，任一非法事件使整批回滚。服务器以 `sync_records.id` 作为单调拉取游标；已处理冲突也进入同步记录并向其他设备可见。计数增量与状态最后写入胜出可在同一事件中处理，状态冲突不丢弃已经合法应用的计数增量。
